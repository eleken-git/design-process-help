# Правила для Claude у цьому репозиторії

Це тренувальний проєкт: дизайнери роблять дизайн у коді та вчаться працювати вдвох через гілки й Pull Request. Ти — руки дизайнера в коді. Дотримуйся правил нижче без нагадувань.

## Архітектура

- Три шари, імпорти тільки вниз: `src/screens → src/components → src/tokens`. Екран не імпортує інший екран, компонент не імпортує екрани, токени не імпортують нічого.
- Стилі тільки через `var(--…)` з `src/tokens`. Не пиши «сирі» кольори й розміри в компонентах і екранах. Немає потрібного токена — запропонуй додати його окремою гілкою `ds/tokens-…`.
- Компонент для одного екрана — у `src/screens/<екран>/components/`. У `src/components` лише те, що потрібне двом і більше екранам.
- Кожен спільний компонент і кожен його варіант має бути на екрані `#/ui-kit` (`src/screens/ui-kit/UiKit.tsx`). Додав варіант — додай його туди.

## Гілки і PR

- Ніколи не коміть у `main`. Перед новою задачею: `git switch main && git pull && git switch -c <гілка>`.
- Назви гілок: `feat/<екран>-<що>` — зміни в `src/screens/<екран>`; `ds/<компонент>-<що>` — зміни в `src/components` або `src/tokens`; `fix/<що>` — виправлення.
- У гілці `feat/*` не змінюй файли в `src/components` і `src/tokens`. Якщо задача цього потребує — зупинись, поясни користувачу і запропонуй окрему гілку `ds/*` від свіжого `main`.
- Новий проп або токен — з дефолтом, який зберігає поточний вигляд. Зміна дефолту, перейменування або видалення — breaking change: спитай користувача, знайди всі використання (`grep -rn "<Button" src`), онови їх у тому ж PR.
- Коміти маленькі, повідомлення у форматі `<область>: <що зроблено>`, напр. `dashboard: картка відтоку`.
- Перед push і PR: `npm run typecheck && npm run build`. Якщо падає — виправ, а не пропускай.
- Якщо змінював `docs/3d/`: ще `npm run test:e2e` і переглянь кадри в `test-results/frames/<епізод>/` — нічого не має лягати на текст.
- PR відкривай через `gh pr create`, заповнюй шаблон `.github/PULL_REQUEST_TEMPLATE.md`. Для `ds/*` обовʼязково скриншот `#/ui-kit`.
- Не роби force push. Не зливай PR сам — merge робить людина після ревʼю.
- Конфлікт при `git merge main`: покажи користувачу обидві версії рядків простими словами і запитай, яку лишити. Не вирішуй мовчки.

## Команди

- `npm install` — один раз після клонування
- `npm run dev` — застосунок на http://localhost:5173 (екрани: `#/dashboard`, `#/settings`, `#/ui-kit`)
- `npm run typecheck` і `npm run build` — перевірка перед PR
- `npm run test:e2e` — Playwright: екрани застосунку, меню презентації, накладання в 3D-епізодах (перший раз: `npx playwright install chromium`)
