# AGENTS.md: README для агентів

**Джерело:** agents.md — простий відкритий формат для інструкцій AI-агентам, https://agents.md/ (репозиторій agentsmd/agents.md на GitHub). Формат веде Agentic AI Foundation під Linux Foundation.
**Формат оригіналу:** коротка сторінка-пояснення англійською з прикладами і відповідями на часті питання.
**Для кого цей переказ:** UX/UI дизайнери, які роблять дизайн у коді через Claude і не є програмістами.

## Що це простими словами

`README.md` у проєкті пишуть для людей: про що проєкт, як почати, як долучитися. AI-агенту потрібне інше: як зібрати проєкт, як його перевірити, які в команді домовленості, чого не робити. Якщо покласти це в README, він роздується і стане нечитабельним для людей. Тому з'явився окремий файл — `AGENTS.md`, «README для агентів»: одне передбачуване місце, де агент знаходить контекст та інструкції.

Формат навмисно простий: звичайний markdown без обов'язкових полів. Один такий файл читають десятки агентів — Codex від OpenAI, Cursor, Copilot від GitHub, Gemini CLI, Jules від Google, Devin, Factory, Amp, Zed, Warp, Windsurf та інші. Ним користуються понад 60 тисяч відкритих проєктів.

## Що зазвичай пишуть

- Огляд проєкту: що це і як влаштовано.
- Команди: як встановити залежності, запустити, зібрати, протестувати.
- Стиль коду і домовленості команди.
- Інструкції з тестування: які перевірки мають пройти до злиття.
- Правила для комітів і Pull Request: формат назви, що перевірити перед відправкою.
- Питання безпеки: що не комітити, з чим бути обережним.
- Усе, що ти сказав би новому колезі в перший день.

## Як це працює

- **Агент сам запускає перевірки.** Якщо в файлі перелічені команди тестів, агент виконає їх і виправить помилки, перш ніж вважати задачу зробленою.
- **Кілька файлів у великому репозиторії.** У кожен підпроєкт можна покласти свій `AGENTS.md`; агент читає найближчий до файла, який редагує. У головному репозиторії OpenAI таких файлів 88.
- **Пріоритети.** Найближчий файл перемагає дальший, а пряме прохання людини в чаті перемагає будь-який файл.
- **Живий документ.** Файл оновлюють, коли змінюються правила, як будь-яку іншу документацію.
- **Перехід зі старих файлів.** Старі файли з іншими назвами перейменовують в `AGENTS.md`, а для сумісності лишають символічне посилання.

## Приклад із сайту

Файл з трьох розділів: підказки по середовищу (як запустити пакет, як додати новий), інструкції з тестування (де лежить план CI, як запустити всі перевірки, як зосередитись на одному тесті, «додавай тести до коду, який змінюєш, навіть якщо ніхто не просив»), правила для PR (формат назви, що запустити перед комітом).

## Чому окремий файл, а не ще один власний формат

Автори кажуть прямо: замість того, щоб кожен агент вимагав свій файл, обрали назву і формат, які підійдуть усім. Мета — дати агентам чітке передбачуване місце для інструкцій, лишити README коротким і людським, і не прив'язувати команди до одного продукту.

## Терміни простими словами

- **README.md** — вступ до проєкту для людей.
- **AGENTS.md** — вступ до проєкту для AI-агентів.
- **CLAUDE.md** — те саме для Claude Code; Claude читає саме цей файл.
- **Коментар до PR / інструкція для комітів** — правила, як описувати зміни.
- **Символічне посилання** — «ярлик» на файл, щоб він був доступний під двома назвами.

## Як це стосується дизайнерів, які роблять дизайн у коді через Claude

- Наш `AGENTS.md` — і є такий файл: три шари архітектури, токени замість «сирих» значень, гілки і PR, що робити з конфліктом. Агент виконує це без нагадувань.
- `CLAUDE.md` у нас лише відсилає до `AGENTS.md`, тому колега, який працює через Codex або Cursor, отримує ті самі правила. Одні правила на всіх агентів.
- Правило «пряме прохання в чаті важливіше за файл» пояснює, чому агент може відступити від правил, якщо ти прямо попросиш, і чому варто просити обережно.
- Пункт «агент сам запускає перевірки» — це наші `npm run typecheck && npm run build` перед PR: якщо вони записані у файлі, агент їх не пропустить.
- Дизайнер може і має писати в такий файл: як називати компоненти, де живуть токени, що показувати в UI kit. Це не код, це домовленості.
